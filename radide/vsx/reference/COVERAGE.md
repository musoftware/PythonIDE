Status words: *implemented* - does what VS Code does; *implemented (Monaco)* - an editor command the bundled Monaco runs on the active editor; *accepted (no-op)* - RAD IDE has no such part (second editor group, Test Explorer, notebook editor ...), the command resolves like VS Code would with that part unavailable; *no UI (resolves undefined)* - a VS Code command RAD IDE has no UI for: `executeCommand` resolves `undefined` (logged once to the Extension Host output) instead of rejecting, ids VS Code does not know reject with `command 'x' not found`. API: *honoured* - an option / data member RAD IDE reads; *consumed* - a provider method RAD IDE calls; *stub* - present with VS Code's type but inert (events that cannot fire in RAD IDE, e.g. `window.onDidChangeTextEditorViewColumn` with one editor group, `env.onDidChangeShell`); *ignored* / *not-consumed* - accepted but without effect.

### What cannot exist in RAD IDE (behaves like VS Code without that UI)

* Notebook editor / interactive window: serializers, controllers and `executeDataToNotebook` work; `showNotebookDocument` returns an editor object, notebook commands and events are inert.
* Chat / language models / MCP: `chat.createChatParticipant`, `lm.registerTool`, `lm.registerLanguageModelChatProvider`, MCP definition providers register; nothing calls them; `lm.selectChatModels` resolves `[]`.
* Test Explorer, SCM view, comments UI, Timeline view: controllers / providers are created with VS Code's shapes (`tests.createTestController`, `scm.createSourceControl`, `comments.createCommentController`, `workspace.registerTimelineProvider`) but are not shown.
* Editor groups / auxiliary windows: one editor group; split / move-to-group commands are accepted no-ops; `workbench.action.moveEditorToNewWindow` floats a webview panel as its own window.
* Port forwarding, remote, workspace trust: `asExternalUri` returns the URI, every folder is trusted, `registerPortAttributesProvider` registers.
* Menus without a RAD IDE surface (scm/*, testing/*, notebook/*, comments/*, terminal/context, webview/context, explorer/context, debug/*): ignored.
