# الدرس 9: رسوم الوضع 13h ومصممات الألعاب

**في هذا الدرس ستتعلم:**

- وضع الرسوم **13h**: شاشة 320 × 200 بـ 256 لونًا، ذاكرتها عند `A000:0000`.
- رسم البكسلات من QBasic وباسكال و C.
- لوحة الألوان (Palette) وكيف تغيّر لونًا بمنفذ الـ VGA.
- مصممات الألعاب في RAD IDE: ارسم الشاشة، فيولّد البرنامج: **DOS Mode 13h** و**Atari 2600** و**NES** و**Game Boy**.

## الوضع 13h

كانت أغلب ألعاب DOS في أوائل التسعينيات تعمل في الوضع **13h** لبطاقة VGA: 320 بكسلًا عرضًا و200 ارتفاعًا، وكل بكسل بايت واحد هو رقم لونه (من 0 إلى 255) في لوحة ألوان من 256 لونًا. ذاكرة الشاشة كتلة واحدة من 64000 بايت عند `A000:0000`، فالبكسل `(x, y)` عند الإزاحة:

```text
offset = y * 320 + x
```

ندخل هذا الوضع بخدمة البيوس `INT 10h` و`AX = 0013h`، ونعود إلى النص بـ `AX = 0003h`.

## من QBasic

QBasic يعطيك أوامر رسم جاهزة:

<!-- test: {"keys": "x"} -->

```dos-qbasic run
SCREEN 13
FOR C = 0 TO 255
    LINE (C + 32, 150)-(C + 32, 199), C
NEXT C
CIRCLE (160, 70), 50, 14
PAINT (160, 70), 4, 14
LINE (20, 20)-(80, 60), 2, BF
PSET (300, 10), 15
K$ = INPUT$(1)
SCREEN 0
PRINT "Back in text mode."
END
```

```text output
Back in text mode.
```

| الأمر | العمل |
|---|---|
| `SCREEN 13` و`SCREEN 0` | الرسوم 320 × 200 × 256، ثم العودة إلى النص |
| `PSET (x, y), لون` | بكسل واحد |
| `LINE (x1, y1)-(x2, y2), لون` | خط، ومع `B` مستطيل، ومع `BF` مستطيل ممتلئ |
| `CIRCLE (x, y), نصف القطر, لون` | دائرة |
| `PAINT (x, y), لون, لون الحد` | تعبئة منطقة |
| `INPUT$(1)` | ينتظر مفتاحًا واحدًا |

## من باسكال: الكتابة في الذاكرة

في باسكال نكتب في الذاكرة مباشرة بالمصفوفة الخاصة `Mem[مقطع:إزاحة]`:

<!-- test: {"keys": "x", "mode13": true} -->

```dos-pascal run
program Plasma;
uses Crt, Dos;
var
  R: Registers;
  X, Y: Integer;
begin
  R.AX := $0013;
  Intr($10, R);                         { mode 13h }
  for Y := 0 to 199 do
    for X := 0 to 319 do
      Mem[$A000:Y * 320 + X] := (X xor Y) and 255;
  ReadKey;
  R.AX := $0003;
  Intr($10, R);                         { back to text mode }
  WriteLn('Pattern drawn: ', 320 * 200, ' pixels.');
end.
```

```text output
Pattern drawn: 64000 pixels.
```

`Intr($10, R)` من وحدة `Dos` يستدعي المقاطعة بقيم السجل `R`. وعند التشغيل الملتقط تحفظ RAD IDE آخر إطار رسومي قبل العودة إلى النص، وتعرضه **Tools > Retro > DOS Programming > Show Last DOS Screen** (آخر شاشة DOS).

## من C: لوحة الألوان

كل رقم لون يقابل ثلاث قيم (أحمر وأخضر وأزرق) من 0 إلى 63 في محوّل الألوان (DAC) لبطاقة VGA. نغيّرها بالكتابة في المنفذين `3C8h` (رقم اللون) و`3C9h` (القيم الثلاث بالترتيب):

<!-- test: {"keys": "x", "mode13": true} -->

```dos-c run
#include <stdio.h>
#include <conio.h>
#include <dos.h>

unsigned char far *vga = (unsigned char far *)0xA0000000L;

void set_mode(unsigned char mode)
{
    union REGS r;
    r.h.ah = 0;
    r.h.al = mode;
    int86(0x10, &r, &r);
}

int main(void)
{
    int x, y, i;
    set_mode(0x13);
    for (i = 0; i < 64; i++) {          /* colours 64..127: black -> red */
        outp(0x3C8, 64 + i);
        outp(0x3C9, i);
        outp(0x3C9, 0);
        outp(0x3C9, 0);
    }
    for (y = 0; y < 200; y++)
        for (x = 0; x < 320; x++)
            vga[y * 320 + x] = (unsigned char)(64 + (x / 5) % 64);
    getch();
    set_mode(0x03);
    printf("Red gradient done.\n");
    return 0;
}
```

```text output
Red gradient done.
```

> **لماذا لا نرسم كل إطار مباشرة؟** في الألعاب ترسم الصورة في «مخزن خلفي» (مصفوفة من 64000 بايت في الذاكرة) ثم تنسخها إلى `A000:0000` دفعة واحدة بعد انتظار عودة شعاع الشاشة (المنفذ `3DAh`)، فلا ترتعش الصورة.

## مصممات الألعاب: ارسم ثم ولّد

بأسلوب Visual Basic: بدل أن تكتب كل بكسل بالكود، ارسم الشاشة بالفأرة ودع RAD IDE تكتب البيانات والبرنامج. افتح **Tools > Retro > Game Designers** (أدوات > ريترو > مصممات الألعاب):

| العنصر | النظام | الملف | ما يولّده |
|---|---|---|---|
| **New DOS Mode 13h Screen...** | DOS، VGA 13h | `.m13scr` | خلفية 320 × 200، وخريطة مربعات 16 × 16، وشخصيات (Sprites) بلون شفاف، ولوحة 256 لونًا؛ وبرامج بـ QBasic (يبنيها FreeBASIC) و C (Open Watcom) و NASM (ملف `.COM` فيه كل شيء) |
| **New Atari 2600 Screen...** | أتاري 2600 | `.a26scr` | خلفية الملعب (Playfield) لكل سطر مسح، ولاعبان وقذيفتان وكرة؛ نواة رسم بالمجمّع DASM بنظام NTSC أو PAL |
| **New NES Screen / Level...** | نينتندو NES | `.nesscr` | جدول الأسماء (Nametable) ولوحات الألوان لكل مربع 16 × 16 وشخصيات؛ مستوى من 1 إلى 8 شاشات مع تمرير، بالمجمّع ca65 |
| **New Game Boy Map...** | جيم بوي | `.gbmap` | الخلفية والنافذة والشخصيات ولوحات BGP و OBP؛ برنامج بالمجمّع RGBDS |

في كل مصمم:

1. **الطبقات** (Layers) على اليسار: الخلفية والمربعات وطبقة **Collision** (التصادم) التي تحدد الجدران والمخاطر، وتُصدَّر جدولًا تقرؤه لعبتك.
2. **الأدوات**: تحديد، قلم، ممحاة، تعبئة، مستطيل، التقاط لون (الزر الأيمن يمسح).
3. **Properties** (الخصائص): خصائص الشخصية المختارة، أو إعدادات الشاشة إن لم تختر شيئًا (نظام التلفاز، عدد الشاشات، لغة برنامج DOS في الخاصية **target**...).
4. **Build && Run** (بناء وتشغيل): يولّد الكود ويبنيه بالأداة المناسبة، ثم يتحقق من النتيجة **دون محاكي** (مثلًا يشغّل برنامج DOS في محاكي 8086 الداخلي ويقارن ذاكرة الشاشة بالتصميم بكسلًا ببكسل، ويعدّ أسطر إطار الأتاري 2600 بدقة)، ثم يفتح المحاكي: **DOSBox-X** أو **Stella** أو **Mesen** أو **mGBA**.

إن كان مشروعك مفتوحًا تُحفظ التصاميم في المجلد `Designs` منه، و**كل حفظ** يعيد توليد الكود في `Designs/gen/<الاسم>/`. افتح الملفات المولّدة وادرسها: برنامج الوضع 13h بلغة C مثلًا يقرأ ملف اللوحة `.PAL` ويضبط الألوان بـ `outp(0x3C8, ...)` و`outp(0x3C9, ...)` كما فعلنا هنا، وبرنامج QBasic يضبطها بالأمر `PALETTE`، ثم يرسمان الخلفية والمربعات والشخصيات.

في المجلد `samples/Tests/Retro/DesignSamples` أمثلة جاهزة: `Cave.m13scr` (DOS) و`Castle.a26scr` (أتاري) و`Meadow.nesscr` (NES) و`Town.gbmap` (جيم بوي). افتحها من **Open Game Design...** واضغط **Build && Run**.

> **تمرين:** أنشئ **New DOS Mode 13h Screen...**، وارسم أرضًا بالمربعات وجدارًا في طبقة Collision، وأضف شخصية. اختر في الخصائص (دون تحديد شيء) القيمة `watcom` للخاصية **target** (برنامج C؛ و`freebasic` لـ QBasic و`nasm` لملف `.COM`)، ثم **Build && Run**. افتح الملف `.C` المولَّد وابحث عن الحلقة التي ترسم المربعات.
