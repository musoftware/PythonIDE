# الدرس 5: تصحيح أخطاء الخادم: نقاط التوقف في Node.js

**في هذا الدرس ستتعلم:**

- تشغيل الموقع مع **مصحح الأخطاء** (debugger) بـ `F5`.
- وضع **نقاط التوقف** (breakpoints) في كود الخادم، وإيقاف الطلب عندها.
- قراءة المتغيرات في نوافذ **Locals** و**Watch** و**Call Stack**، وتنفيذ أوامر في **Immediate**.
- التنقل خطوة بخطوة: `F10` و`F11` و`Shift+F11`.

## لماذا مصحح الأخطاء؟

`console.log` مفيدة، لكنها تشبه أن تسأل المريض «أين يؤلمك؟» عبر الهاتف. أما مصحح الأخطاء فيشبه **جهاز الأشعة**: يوقف البرنامج في اللحظة التي تختارها، وترى كل المتغيرات وقيمها، ثم تتقدم سطرًا سطرًا وتراقب ما يتغير.

## كيف يعمل التصحيح في RAD IDE؟

عندما تضغط `F5` على موقع Node.js:

1. يعمل الخادم بالأمر `node --inspect-wait ...`، أي ينتظر مصحح الأخطاء قبل أن يبدأ.
2. تتصل به أداة **vscode-js-debug** (المصحح نفسه الذي تستخدمه VS Code). في أول مرة تنزّلها RAD IDE وحدها في `%LOCALAPPDATA%\RADIDE\tools\js-debug`، فتحتاج اتصالًا بالإنترنت مرة واحدة.
3. يبدأ الموقع وتظهر المعاينة كالعادة. لكن أي طلب يصل إلى سطر عليه نقطة توقف **يتوقف** هناك.
4. عندما تحفظ ملفًا يعيد RAD IDE تشغيل الخادم، ويعيد المصحح الاتصال وحده.

## الخطوة 1: نقطة توقف في مسار

افتح مشروع الملاحظات (Express) من الدرس 3، وافتح `app.js`:

1. ضع المؤشر على السطر الأول داخل مسار `POST /api/notes`، أي السطر `const text = String(req.body.text || '').trim();`.
2. اضغط `F9` (**Debug > Toggle Breakpoint**: تبديل نقطة التوقف) أو انقر في الهامش يسار رقم السطر. تظهر دائرة حمراء.
3. اضغط `F5` (**Debug > Start Debugging / Continue**).
4. من REST Client (الدرس 4) أرسل طلب `POST` بالجسم `{ "text": "اختبار المصحح" }`.

يتوقف الخادم عند السطر، ويُظلَّل باللون الأصفر، ولا يصل الرد إلى REST Client بعد (هو ينتظر).

## الخطوة 2: افحص المتغيرات

| النافذة | بالعربية | ما تعرضه |
|---|---|---|
| **Locals** | المتغيرات المحلية | متغيرات الدالة الحالية: `req` و`res`... افتح `req` ثم `body` لترى `text` |
| **Watch** | المراقبة | تعبيرات تكتبها بنفسك وتتابع قيمتها، مثل `notes.length` |
| **Call Stack** | مكدس الاستدعاءات | سلسلة الدوال التي أوصلتك إلى هنا (دوال Express ثم دالتك) |
| **Immediate** | الأوامر الفورية | اكتب أي تعبير واضغط Enter لترى قيمته، مثل `req.body` أو `notes.map(n => n.text)` |

ويمكنك أيضًا وضع مؤشر الفأرة فوق أي متغير في المحرر لترى قيمته.

## الخطوة 3: تقدّم خطوة بخطوة

| المفتاح | الأمر | المعنى |
|---|---|---|
| `F10` | **Step Over** (خطوة فوق) | نفّذ السطر الحالي وانتقل للتالي (دون الدخول في الدوال) |
| `F11` | **Step Into** (خطوة إلى الداخل) | ادخل داخل الدالة التي يستدعيها السطر |
| `Shift+F11` | **Step Out** (خطوة إلى الخارج) | أكمل الدالة الحالية وارجع لمن استدعاها |
| `F5` | **Continue** (متابعة) | أكمل التشغيل حتى نقطة التوقف التالية |
| `Shift+F5` | **Stop Debugging** (إيقاف تصحيح الأخطاء) | أوقف الخادم والمصحح |

اضغط `F10` عدة مرات وراقب `text` ثم `note` في **Locals**. بعد `F5` يكمل الخادم ويصل الرد `201` إلى REST Client.

## التوقف عند الأخطاء

إن رمى الكود خطأً **لم يلتقطه أحد** (uncaught)، مثل خطأ عند بدء الخادم أو داخل `setTimeout`، يتوقف المصحح عند السطر الذي حدث فيه الخطأ، فترى السبب مباشرة. يتحكم في ذلك الخيار **Debug > Break on Exceptions** (مفعّل افتراضيًا).

انتبه: Express **يلتقط** الأخطاء التي تحدث داخل المسارات بنفسه، ويرد بالحالة `500` ويطبع تفاصيل الخطأ في **Output**، فلا يتوقف المصحح عندها. لفحص خطأ داخل مسار، ضع نقطة توقف في أول المسار وتقدّم بـ `F10` حتى تصل إلى السطر الذي ينهار.

## نصائح عملية

- **نقطة توقف شرطية:** إن كان المسار يُستدعى كثيرًا، ضع المؤشر على سطر النقطة واختر **Debug > Breakpoint Condition...** واكتب شرطًا مثل `req.body.text === 'x'`، فلا يتوقف إلا عندما يتحقق. وبديل سريع: اكتب في الكود `if (req.body.text === 'x') { debugger; }`. الكلمة `debugger` نفسها نقطة توقف، ولا تنسَ حذفها بعد الانتهاء.
- **Run to Cursor:** من **Debug > Run to Cursor** يكمل البرنامج حتى السطر الذي فيه المؤشر.
- **`console.log` ما زالت مفيدة:** ناتجها يظهر في **Output** أثناء التصحيح أيضًا.
- **TypeScript وNestJS:** نقاط التوقف تعمل في ملفات `.ts` مباشرة (الدرس 8).
- إن لم يتوقف المصحح، تأكد أنك شغّلت بـ `F5` لا `Ctrl+F5`، وأن الطلب يمر فعلًا بالسطر الذي عليه النقطة.

## تمرين: اصطد الخطأ

هذه الدالة يُفترض أن تحسب متوسط درجات الملاحظات المنجزة، لكنها تعطي نتيجة خاطئة. شغّلها، وضع نقطة توقف داخل الحلقة (أو استخدم `console.log`) لترى قيمة `i` في كل دورة، ثم أصلحها.

```js exercise
function averageDone(items) {
    let sum = 0;
    let count = 0;
    for (let i = 1; i <= items.length; i++) {
        if (items[i] && items[i].done) {
            sum += items[i].score;
            count++;
        }
    }
    return count === 0 ? 0 : sum / count;
}

const items = [
    { score: 90, done: true },
    { score: 40, done: false },
    { score: 70, done: true },
];
console.log(averageDone(items));
```

```js solution
function averageDone(items) {
    let sum = 0;
    let count = 0;
    for (let i = 0; i < items.length; i++) {
        if (items[i].done) {
            sum += items[i].score;
            count++;
        }
    }
    return count === 0 ? 0 : sum / count;
}

const items = [
    { score: 90, done: true },
    { score: 40, done: false },
    { score: 70, done: true },
];
console.log(averageDone(items));
```

```text output
80
```

**أين كان الخطأ؟** الحلقة بدأت من `1` بدل `0` فتخطت العنصر الأول، وانتهت عند `items.length` الذي لا يوجد عنصر بفهرسه (لذلك احتاج الكود القديم إلى الفحص `items[i] &&` ليتجنب الانهيار). في المصحح كنت سترى `i = 1` في أول دورة مباشرة.

## الخلاصة

- `F5` يشغّل الموقع مع vscode-js-debug (تنزل تلقائيًا أول مرة)، و`F9` نقطة توقف.
- عند التوقف: **Locals** و**Watch** و**Call Stack** و**Immediate**، وتلميح الفأرة فوق المتغيرات.
- `F10` و`F11` و`Shift+F11` للخطوات، و`F5` للمتابعة، و`Shift+F5` للإيقاف.
- الكلمة `debugger` نقطة توقف داخل الكود، والتوقف عند الأخطاء غير الملتقطة يكشف السبب فورًا.
