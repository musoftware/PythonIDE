# الدرس 8: معالج الترحيل: تحويل مشروع إلى RAD IDE

في الدروس السابقة عملنا على مشاريع Visual Studio **في مكانها**. لكن أحيانًا تريد شيئًا آخر: أن تحوّل برنامج Windows Forms قديمًا إلى **Python**، أو إلى مشروع **C# (GUI Bridge)** يعمل بأسلوب RAD IDE، أو أن تحوّل مشروع **VB6** إلى **VB.NET**. هذا عمل **معالج الترحيل** (Migration Wizard).

> **تشبيه:** الترحيل مثل **الانتقال إلى بيت جديد**: تحزم الأثاث (النماذج والأدوات)، وتنقله إلى البيت الجديد (اللغة الجديدة)، وترتبه في الغرف المناسبة. بعض الأشياء تُنقل كما هي، وبعضها يحتاج إلى تعديل ليناسب المكان الجديد، وتكتب قائمة بما لم يُنقل بعد. والبيت القديم يبقى كما هو.

## متى تستخدم الترحيل؟

| أريد أن... | الحل |
|---|---|
| أكمل العمل على المشروع ويبقى مشروع Visual Studio | **File > Open Project...** (الفتح في المكان، الدروس 1 إلى 7) |
| أحوّل البرنامج إلى لغة أخرى (Python مثلًا) | **معالج الترحيل** |
| أحوّل مشروع VB6 إلى VB.NET أو إلى RAD BASIC | **معالج الترحيل** |
| أحوّل نموذج Windows Forms إلى مشروع GUI Bridge في RAD IDE | **معالج الترحيل** |

## ما المشاريع التي يقرؤها المعالج؟

| المصدر | الملفات |
|---|---|
| Visual Basic 6 | `.vbp` و`.frm` |
| Visual Studio (C# وVB.NET مع Windows Forms) | `.sln` و`.csproj` و`.vbproj` |
| Delphi / Lazarus | `.dproj` و`.dpr` و`.lpi` و`.lpr` |
| Qt Designer | `.ui` |

## فتح المعالج

طريقتان:

- **File > Migrate Project...** (ملف > ترحيل المشروع...).
- أو من **Solution Explorer** بعد فتح الحل: انقر بالزر الأيمن على الحل واختر **Migrate to a RAD IDE project...**.

## صفحات المعالج خطوة بخطوة

### 1) Project to migrate (المشروع المراد ترحيله)

اضغط **File...** واختر ملف المشروع (`.sln` أو `.csproj` أو `.vbproj` أو `.vbp`...)، أو **Folder...** واختر مجلده. يعرض المعالج ما وجده، مثل: `Visual Studio project Shop: 3 form(s), 2 module(s)`.

### 2) Target (الهدف)

اختر إلى أين تريد الترحيل. الأهداف **بالخط العريض** تحوّل كود الأحداث **بالقواعد** (rules) تلقائيًا، والباقي ينقل النماذج والأدوات ويضع لكل حدث دالة فيها الكود الأصلي **كتعليقات** لتترجمه بنفسك (أو بالذكاء الاصطناعي):

| المصدر | أهداف تُحوَّل بالقواعد |
|---|---|
| C# (Windows Forms) | Python (Tkinter)، Python (Qt)، ونفس اللغة: **C# (GUI Bridge, .NET)** |
| VB.NET (Windows Forms) | Python (Tkinter)، Python (Qt)، Visual Basic (RAD BASIC) |
| VB6 | Python (Tkinter)، Python (Qt)، Visual Basic (RAD BASIC، يعمل كود VB6 كما هو)، **VB.NET Windows Forms** (مشروع Visual Studio `.vbproj`) |

وتظهر بعدها كل لغات RAD IDE الأخرى (Java وGo وRust...) كأهداف بالتعليقات.

### 3) Options (الخيارات)

| الخيار | معناه |
|---|---|
| **New project folder** | مجلد المشروع الجديد (يقترح المعالج اسمًا مثل `Shop_python_tk` بجانب الأصل) |
| **Write the project into a new folder (recommended)** | الكتابة في مجلد جديد (الأفضل) |
| **In place** | الكتابة بجانب الملفات الأصلية، فقط إذا لم يُستبدل أي ملف |
| **Event code** | تحويل كود الأحداث بالقواعد، أو القواعد ثم الذكاء الاصطناعي لما لم تحوّله القواعد، أو إبقاء الكود الأصلي كتعليقات فقط |
| **Copy the original project into _original/** | نسخة من الأصل داخل المشروع الجديد للرجوع إليها |

خيار الذكاء الاصطناعي يحتاج إلى إعداده أولًا من **Tools > Options... > AI** (أدوات > خيارات...).

### 4) Preview of the mapping (معاينة التحويل)

قبل الكتابة يعرض المعالج **شجرة** بكل ما سيحدث: النماذج، والأدوات وما يقابل كل أداة في الهدف، والأحداث، والوحدات، والعناصر غير المدعومة. راجعها جيدًا، ثم اضغط **Migrate**.

### 5) Migrating ثم Migration report (التقرير)

يكتب المعالج المشروع الجديد، ثم يعرض **تقرير الترحيل** ويحفظه في الملف `MIGRATION_REPORT.md`. كل عنصر في التقرير له حالة:

| الحالة | معناها |
|---|---|
| **exact** | نُقل كما هو تمامًا |
| **rules** | حُوّل بالقواعد (راجعه سريعًا) |
| **approximate** | حُوّل بأقرب مقابل، وقد يختلف قليلًا في الشكل أو السلوك |
| **AI** | ترجمه الذكاء الاصطناعي (راجعه بعناية) |
| **manual TODO** | لم يُحوَّل: عليك أن تكمله بنفسك، والتقرير يذكر **الملف والسطر** |

في النهاية علّم **Open the migrated project** لفتح المشروع الجديد، و**Open MIGRATION_REPORT.md in the editor** لفتح التقرير.

## مثال: ما الذي تفعله القواعد؟

نموذج Windows Forms فيه هذا المعالج:

```csharp
private void btnHello_Click(object sender, EventArgs e)
{
    string name = txtName.Text.Trim();
    if (name == "")
        MessageBox.Show("اكتب اسمك");
    else
        lblResult.Text = "أهلًا يا " + name;
}
```

عند الترحيل إلى **C# (GUI Bridge, .NET)** يصبح بأسلوب RAD IDE الذي تعلمته في دورة C#:

```csharp
static void btnHello_Click(RadEvent e)
{
    string name = txtName.Text.Trim();
    if (name == "")
        MsgBox("اكتب اسمك");
    else
        lblResult.Text = "أهلًا يا " + name;
}
```

وعند الترحيل إلى **Python (Tkinter)** تُنشأ نافذة Tkinter بنفس الأدوات والمواضع، ودالة Python لكل حدث مكتوبة بالقواعد، والكود الأصلي كتعليق فوقها للمقارنة.

## بعد الترحيل: قائمة مراجعة

1. افتح `MIGRATION_REPORT.md` وابدأ بعناصر **manual TODO**: انقر على الملف والسطر وأكمل الكود.
2. شغّل المشروع (`F5`) وجرّب كل نافذة وكل زر.
3. راجع عناصر **approximate** و**AI**: الشكل والسلوك.
4. لا تحذف `_original/` حتى تنتهي من المراجعة؛ احذفه بعد ذلك إن شئت.
5. احفظ عملك في Git قبل الترحيل وبعده، لتقارن بسهولة.

## أخطاء شائعة

- **الترحيل بدل الفتح في المكان:** إذا كنت تريد فقط تعديل المشروع ويبقى مشروع Visual Studio، فلا تحتاج إلى الترحيل. استخدم **File > Open Project...**.
- **توقع تحويل 100% تلقائي:** القواعد تحوّل معظم كود الأحداث الشائع، لكن المكتبات الخاصة (قواعد بيانات معينة، أو أدوات طرف ثالث) غالبًا تظهر كـ **manual TODO**.
- **اختيار In place في مجلد فيه ملفات بنفس الأسماء:** المعالج يرفض الكتابة فوق الملفات الأصلية. اختر مجلدًا جديدًا.

## الخلاصة

- **الفتح في المكان** للعمل على نفس المشروع، و**الترحيل** لكتابة مشروع جديد بلغة أو تقنية أخرى.
- الصفحات: المشروع ← الهدف ← الخيارات ← المعاينة ← الترحيل ← التقرير `MIGRATION_REPORT.md`.
- حالات التقرير: **exact** و**rules** و**approximate** و**AI** و**manual TODO**.
- بعد الترحيل: أكمل عناصر **manual TODO**، ثم جرّب وراجع.

**مبروك!** أنهيت دليل مشاريع Visual Studio. أنت الآن تستطيع أن تفتح أي حل من Visual Studio في RAD IDE، وتصمم نماذجه، وتبنيه وتصححه، وتدير حزمه، أو ترحّله إلى لغة أخرى.
