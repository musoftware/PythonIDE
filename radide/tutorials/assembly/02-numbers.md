# الدرس 2: الأنظمة العددية: الثنائي والسادس عشر

**في هذا الدرس ستتعلم:**

- لماذا يعمل الحاسوب بالنظام **الثنائي** (Binary).
- النظام **السادس عشر** (Hexadecimal) ولماذا يحبه مبرمجو التجميع.
- التحويل بين العشري والثنائي والسادس عشر.
- البت والبايت والـ word والـ dword والـ qword.
- كيف تُخزَّن الأعداد **السالبة** (المتمم الثنائي).
- طباعة الأعداد بـ `printf`.

## لماذا الثنائي؟

داخل المعالج ملايين من المفاتيح الإلكترونية الصغيرة (الترانزستورات)، كل مفتاح له حالتان فقط: **مفتوح** أو **مغلق**، أي **0** أو **1**. هذه الخانة الواحدة اسمها **بت** (bit). وكل الأرقام والحروف والصور داخل الحاسوب مجرد بتات.

في النظام العشري الذي نعرفه، كل خانة قيمتها أكبر بعشر مرات من التي على يمينها (آحاد، عشرات، مئات). في الثنائي كل خانة **ضعف** التي على يمينها:

| الخانة | 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
|---|---|---|---|---|---|---|---|---|
| القيمة | 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |

مثال: العدد الثنائي `1101` = 8 + 4 + 0 + 1 = **13**.

### من العشري إلى الثنائي

اقسم على 2 مرة بعد مرة واكتب الباقي، ثم اقرأ البواقي من الأسفل إلى الأعلى:

```text
13 / 2 = 6  الباقي 1
 6 / 2 = 3  الباقي 0
 3 / 2 = 1  الباقي 1
 1 / 2 = 0  الباقي 1
النتيجة: 1101
```

## البت والبايت وأخواتهما

| الاسم | عدد البتات | أكبر عدد موجب (بلا إشارة) | اسمه في NASM |
|---|---|---|---|
| bit (بت) | 1 | 1 | - |
| byte (بايت) | 8 | 255 | `byte` / `db` |
| word (كلمة) | 16 | 65535 | `word` / `dw` |
| dword (كلمة مزدوجة) | 32 | 4294967295 | `dword` / `dd` |
| qword (كلمة رباعية) | 64 | 18446744073709551615 | `qword` / `dq` |

المعالج الذي نبرمجه **64 بت**: مسجلاته الكبيرة تتسع لـ qword كاملة.

## النظام السادس عشر (Hex)

الأعداد الثنائية طويلة ومتعبة للعين. الحل: نجمع كل **4 بتات** في خانة واحدة. أربعة بتات تعطي 16 احتمالًا (من 0 إلى 15)، فنحتاج 16 رمزًا: الأرقام `0-9` ثم الحروف `A-F`:

| عشري | ثنائي | سادس عشري |
|---|---|---|
| 0 | 0000 | 0 |
| 5 | 0101 | 5 |
| 9 | 1001 | 9 |
| 10 | 1010 | A |
| 11 | 1011 | B |
| 12 | 1100 | C |
| 13 | 1101 | D |
| 14 | 1110 | E |
| 15 | 1111 | F |

إذن البايت (8 بتات) = خانتان سادس عشريتان بالضبط: `11001010` = `1100 1010` = `CA`. لهذا ترى البايتات دائمًا مكتوبة هكذا: `48 83 EC 28`.

ولتحويل `CA` إلى العشري: C = 12، وA = 10، فالقيمة = 12 × 16 + 10 = **202**.

## كتابة الأعداد في NASM

يقبل NASM العدد بأي نظام، والنتيجة داخل المعالج واحدة:

| النظام | أمثلة |
|---|---|
| عشري | `10`، `255` |
| سادس عشري | `0x0A`، `0Ah`، `0FFh` (إذا بدأ بحرف ضع قبله 0) |
| ثنائي | `0b1010`، `1010b` |
| ثماني | `12o`، `0o12` |
| حرف | `'A'` (قيمته 65) |

## الطباعة بـ printf

الدالة `printf` من مكتبة C تطبع **نصًّا منسّقًا**: المعامل الأول نص فيه علامات مثل `%d` (عدد عشري)، والمعاملات التالية القيم التي توضع مكانها. في ويندوز 64 بت المعاملات بالترتيب في `rcx` ثم `rdx` ثم `r8` ثم `r9`:

```asm run
default rel
global main
extern printf

section .data
    fmt db "dec=%d hex=%X oct=%o", 10, 0

section .text
main:
    sub rsp, 40
    lea rcx, [fmt]       ; 1: نص التنسيق
    mov edx, 255         ; 2: لـ %d
    mov r8d, 255         ; 3: لـ %X
    mov r9d, 255         ; 4: لـ %o
    call printf
    xor eax, eax
    add rsp, 40
    ret
```

```text output
dec=255 hex=FF oct=377
```

- `mov edx, 255` ضع العدد 255 في `edx` (النصف الأدنى 32 بت من `rdx`؛ الدرس القادم يشرح هذه الأسماء).
- الرقم `10` في آخر النص هو رمز **السطر الجديد**، لأن `printf` لا تنزل سطرًا وحدها كما تفعل `puts`.

علامات التنسيق المفيدة: `%d` عدد بإشارة، و`%u` عدد بلا إشارة، و`%X` سادس عشري، و`%o` ثماني، و`%c` حرف، و`%s` نص، و`%lld` و`%llX` لعدد 64 بت كامل.

## نفس العدد بثلاث كتابات

```asm run
default rel
global main
extern printf

section .data
    fmt db "%d %d %d", 10, 0

section .text
main:
    sub rsp, 40
    lea rcx, [fmt]
    mov edx, 0b1010      ; ثنائي
    mov r8d, 0Ah         ; سادس عشري
    mov r9d, 12o         ; ثماني
    call printf
    xor eax, eax
    add rsp, 40
    ret
```

```text output
10 10 10
```

## الأعداد السالبة: المتمم الثنائي

كيف يخزن المعالج العدد `-1` وليس عنده إلا 0 و1؟ يستخدم طريقة اسمها **المتمم الثنائي** (Two's Complement):

1. اكتب العدد الموجب: `1` = `00000001`.
2. اقلب كل البتات: `11111110`.
3. أضف 1: `11111111`.

إذن `-1` في بايت واحد = `FF`، وفي 32 بت = `FFFFFFFF`. **نفس البتات** يمكن قراءتها كعدد بإشارة (‎-1) أو بلا إشارة (4294967295). المعالج لا يعرف الفرق؛ **أنت** من يقرر كيف تفسّرها:

```asm run
default rel
global main
extern printf

section .data
    fmt db "signed=%d unsigned=%u hex=%X", 10, 0

section .text
main:
    sub rsp, 40
    lea rcx, [fmt]
    mov edx, -1
    mov r8d, -1
    mov r9d, -1
    call printf
    xor eax, eax
    add rsp, 40
    ret
```

```text output
signed=-1 unsigned=4294967295 hex=FFFFFFFF
```

في المتمم الثنائي: إذا كان **البت الأعلى** 1 فالعدد سالب (عند قراءته بإشارة). لذلك مدى البايت بإشارة من ‎-128 إلى 127، وبلا إشارة من 0 إلى 255.

## الحروف أعداد أيضًا

كل حرف إنجليزي له رقم في جدول **ASCII**: `'A'` = 65 و`'a'` = 97 و`'0'` = 48. لاحظ الفرق بين الرقم `5` والحرف `'5'` (قيمته 53):

```asm run
default rel
global main
extern printf

section .data
    fmt db "%c = %d = 0x%X", 10, 0

section .text
main:
    sub rsp, 40
    lea rcx, [fmt]
    mov edx, 'a'
    mov r8d, 'a'
    mov r9d, 'a'
    call printf
    xor eax, eax
    add rsp, 40
    ret
```

```text output
a = 97 = 0x61
```

> **تنبيه:** المسجلات الأربعة `rcx` و`rdx` و`r8` و`r9` تكفي لنص التنسيق وثلاث قيم فقط. إذا كتبت أربع علامات `%` فستأخذ `printf` القيمة الرابعة من مكان عشوائي في الذاكرة وتطبع رقمًا غريبًا. المعامل الخامس فما بعده يوضع على **المكدس**، وهذا ما سنتعلمه في الدرس 9.

## الخلاصة

- الحاسوب يعمل بالبتات (0 و1)، والبايت 8 بتات، وword وdword وqword هي 16 و32 و64 بتًا.
- السادس عشر يختصر كل 4 بتات في خانة: البايت خانتان.
- في NASM: `0x1F` أو `1Fh` للسادس عشر، و`0b101` أو `101b` للثنائي، و`'A'` للحرف.
- الأعداد السالبة بالمتمم الثنائي: نفس البتات تُقرأ بإشارة أو بلا إشارة.
- `printf`: النص في `rcx` ثم القيم في `rdx` و`r8` و`r9`.
