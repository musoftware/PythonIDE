# الدرس 1: ما هي ملفات ECU؟ والحدود القانونية وحدود السلامة

**في هذا الدرس ستتعرف على:**

- معنى **وحدة التحكم الإلكترونية** (ECU) و**البرنامج الثابت** (Firmware).
- ماذا يوجد داخل ملف `.bin` لسيارة مرسيدس أو غيرها: كود ومعايرة وبيانات.
- من أين تأتي هذه الملفات، وأشهر امتداداتها: `.bin` و`.ori` و`.mod` و`.hex` و`.s19` و`.eep`.
- **الحدود القانونية وحدود السلامة**: ما الذي تفعله أدوات RAD IDE وما الذي لا تفعله أبدًا.
- خريطة أدوات RAD IDE لهذا الموضوع.

## السيارة شبكة من الحواسيب الصغيرة

السيارة الحديثة فيها عشرات **وحدات التحكم** (Electronic Control Unit): وحدة المحرك، وناقل الحركة، والفرامل ABS، والوسائد الهوائية، ولوحة العدادات... كل وحدة حاسوب صغير فيه **معالج دقيق** (Microcontroller) وذاكرة **فلاش** يُخزَّن فيها برنامجه.

عندما يقرأ فني محتوى الفلاش ويحفظه في ملف يسمى ذلك **تفريغًا** (Dump)، والملف الناتج هو ما يسميه الناس «ملف الـ bin بتاع العربية». الملف مجرد بايتات، فيها عادة ثلاثة أنواع من المحتوى:

| الجزء | ماذا فيه | كيف يبدو في محرر السادس عشر |
|---|---|---|
| **الكود** | تعليمات المعالج (ARM أو PowerPC أو TriCore...) | بايتات «عشوائية» الشكل، أنتروبيا متوسطة |
| **المعايرة** (Calibration) | جداول وأرقام يقرأها الكود: خرائط ومنحنيات وقيم مفردة | أرقام تتغير ببطء، وصفوف متزايدة (المحاور) |
| **البيانات** | نصوص التعريف ورقم البرنامج والمجاميع الاختبارية والمساحات الفارغة | نص مقروء، و`FF FF FF` في الفراغات |

> **الكود ثابت، والمعايرة هي التي تختلف.** الشركة تكتب برنامجًا واحدًا لعدة سيارات، ثم تضبط الأرقام (المعايرة) لكل محرك وطراز. لذلك معظم العمل الشرعي على هذه الملفات - الإصلاح والبحث والتعليم والضبط - يكون على **خرائط المعايرة**، وهو موضوع الدروس 5 و 6.

## من أين تأتي الملفات؟ وما امتداداتها؟

| الامتداد | المعنى |
|---|---|
| `.bin` `.rom` `.dump` | **ملف خام**: صورة الفلاش بايتًا ببايت، بلا عناوين |
| `.ori` / `.mod` | اصطلاح الورش: **الأصلي** (Original) و**المعدَّل** (Modified)، وهما ملفان خامان |
| `.hex` | **Intel HEX**: نص فيه البايتات مع عناوينها |
| `.s19` `.s28` `.s37` `.mot` | **Motorola S-record**: نص مثل HEX، شائع مع معالجات PowerPC و HC12 |
| `.elf` | ملف تنفيذي من المُترجم، فيه أقسام ورموز (في المشاريع مفتوحة المصدر) |
| `.eep` `.e2p` | تفريغ ذاكرة **EEPROM** صغيرة (24Cxx أو 93Cxx أو 95xxx) |

## لماذا نحفظ الأصل؟ بصمة SHA-256

أول قاعدة في هذا العالم: **لا تعدّل الأصل أبدًا**. احتفظ بنسخة منه، واحسب **بصمته** لتعرف لاحقًا أنه لم يتغير. البصمة تتغير كليًا حتى لو تغير بايت واحد:

```python run
import hashlib

original = bytes(range(256)) * 16          # 4 KB تجريبية (ليست من سيارة)
modified = bytearray(original)
modified[0x123] ^= 0x01                    # بت واحد فقط

h1 = hashlib.sha256(original).hexdigest()
h2 = hashlib.sha256(bytes(modified)).hexdigest()
print("original:", h1[:16])
print("modified:", h2[:16])
print("same?", h1 == h2)
print("changed bytes:", sum(a != b for a, b in zip(original, modified)))
```

```text output
original: c8f5d0341d54d951
modified: c6e68f2b02fae05c
same? False
changed bytes: 1
```

هذا بالضبط ما يفعله **مشروع ECU** في RAD IDE: ينسخ الأصل إلى مجلد `original/`، ويجعله **للقراءة فقط**، ويحفظ بصمته في `ecu.json`. قبل كل **Build** يعيد حساب البصمة، ويرفض البناء إذا تغير الأصل.

## الحدود القانونية وحدود السلامة - اقرأها جيدًا

برنامج السيارة يتحكم في أشياء تمس **حياة الناس**: الفرامل والوسائد الهوائية والمحرك. وتعديله قد يؤثر على **السلامة** و**الضمان** و**قانونية الانبعاثات** وصلاحية السيارة للسير. لذلك:

| مسموح ومفيد | غير مسموح - ولا يوجد في RAD IDE |
|---|---|
| تحليل ملف وحدة **تملكها** أو مخوَّل بإصلاحها | تعطيل مانع التشغيل (Immobilizer) أو استخراج المفاتيح وأرقام PIN |
| البحث والتعليم على ملفات اصطناعية أو مفتوحة المصدر | إلغاء أنظمة الانبعاثات أو تعطيلها أو تزييف فحوصها |
| ضبط معايرة في حدود القانون مع الاحتفاظ بالأصل | التلاعب بعداد المسافات |
| مقارنة نسختين، وتصحيح المجاميع الاختبارية بعد تعديل مشروع | كسر حماية الوصول الأمني أو تعديل رقم الشاسيه (VIN) |

**RAD IDE يقدم أدوات عامة**: صيغ الملفات، والتحليل، والتفكيك، وتحرير الخرائط، والمجاميع الاختبارية. لا توجد فيه قوالب أو إعدادات جاهزة لأي من البنود الممنوعة، ولن تجدها في هذه الدورة. وإذا مررت ببيانات من هذا النوع في ملف، فهي عنده بايتات مثل غيرها، بلا أي أداة خاصة.

عند فتح أول مشروع ECU يظهر **تنبيه مرة واحدة**: «تعديل برامج المركبات قد يؤثر على السلامة والضمان وقانونية الانبعاثات. احتفظ بالأصل والتزم بقوانين بلدك». اضغط «أفهم ذلك» فلا يظهر مرة أخرى في أي أداة.

> **عن ملفات الشركات:** ملفات مرسيدس و Bosch و Continental وغيرها **محمية بحقوق النشر**، وقد تحتوي رقم الشاسيه لسيارة شخص. لا تنزّلها من الإنترنت ولا تنشرها. هذه الدورة تستخدم **ملفات اصطناعية** يكتبها RAD IDE نفسه، و**rusEFI**: مشروع وحدة تحكم مفتوح المصدر (رخصة GPL) تنزّله الاختبارات من صفحته الرسمية على GitHub فقط.

## أدواتك في RAD IDE

| ما تريد | أين |
|---|---|
| مشروع يحفظ الأصل وينشئ نسخة عمل ونسخًا وتقارير | File > New Project > **Firmware** > ECU / Firmware Project (أو قالب ECU Project (Demo Firmware)) |
| فتح أي ملف في منضدة العمل (مثل WinOLS) | Tools > Firmware & ECU > Open Firmware in Workbench... |
| تحليل ملف: المعالج والعنوان والأنتروبيا والنصوص والتفكيك و Ghidra | Tools > Firmware & ECU > Analyze Firmware File... |
| تحويل HEX و S-record و ELF، وتقسيم ودمج | Tools > Firmware & ECU > Firmware Converter... |
| محرر الخرائط الكامل والمقارنة و A2L | Tools > Firmware & ECU > Calibration Maps |
| المجاميع الاختبارية والنسخ والتقارير | Project > ECU Project |
| ملف تجريبي اصطناعي | Tools > Firmware & ECU > Create Synthetic Test Firmware... |
