# الدرس 5: خرائط المعايرة والبحث عنها

**في هذا الدرس:**

- ما هي **الخريطة** (Map) و**المنحنى** (Curve) و**القيمة** (Value).
- **المحاور**: صفوف أرقام متزايدة مثل سرعة المحرك rpm والحمل.
- أشكال تخزين الخريطة في الملف: مع **رأس** أو بلا رأس، صفًا بصف أو عمودًا بعمود.
- كيف يبحث RAD IDE عن الخرائط المحتملة: المحور المتزايد + القيم الناعمة.
- **عرض 2D** للملف كله.

## الخريطة جدول ثنائي الأبعاد

وحدة التحكم لا تحسب كل شيء بمعادلات؛ كثير من القرارات **جداول**: «عند هذه السرعة وهذا الحمل، القيمة كذا». الجدول له:

- **محور X** (مثلًا سرعة المحرك: 500، 1000، 1500 ... rpm)
- **محور Y** (مثلًا الحمل أو ضغط الهواء)
- **القيم**: صفوف × أعمدة، وبين نقاط الجدول يحسب المعالج **بالاستيفاء** (Interpolation).

**المنحنى** جدول بمحور واحد، و**القيمة** رقم واحد (حد أو ثابت). في الملف كلها أرقام 8 أو 16 أو 32 بت.

## اقرأ خريطة بنفسك

أشهر شكل (يُعرف بأسلوب Bosch): بايت أو كلمة لعدد نقاط X، ثم لعدد نقاط Y، ثم المحور X، ثم المحور Y، ثم القيم صفًا بصف. هذه 4×3 مكتوبة في الذاكرة ثم مقروءة:

```python run
import struct

xs = [800, 1600, 2400, 3200]          # rpm
ys = [20, 50, 80]                     # الحمل %
values = [[100, 120, 140, 150],
          [130, 160, 190, 205],
          [150, 190, 230, 250]]

blob = struct.pack(">HH", len(xs), len(ys)) + struct.pack(">4H", *xs) + struct.pack(">3H", *ys)
blob += b"".join(struct.pack(">4H", *row) for row in values)
print(len(blob), "bytes:", blob[:12].hex(" "), "...")

# القراءة كما تفعل الأداة
nx, ny = struct.unpack_from(">HH", blob, 0)
X = struct.unpack_from(f">{nx}H", blob, 4)
Y = struct.unpack_from(f">{ny}H", blob, 4 + 2 * nx)
Z = struct.unpack_from(f">{nx * ny}H", blob, 4 + 2 * (nx + ny))
print("      " + "".join(f"{x:>6}" for x in X))
for j, y in enumerate(Y):
    print(f"{y:>4}% " + "".join(f"{v:>6}" for v in Z[j * nx:(j + 1) * nx]))
```

```text output
42 bytes: 00 04 00 03 03 20 06 40 09 60 0c 80 ...
         800  1600  2400  3200
  20%    100   120   140   150
  50%    130   160   190   205
  80%    150   190   230   250
```

## كيف تجد خريطة في ملف لا تعرفه؟

لا توجد أسماء في الملف. لكن للخرائط **بصمة**:

1. **محور متزايد تمامًا**: 4 إلى 64 رقمًا كل واحد أكبر من الذي قبله (500، 1000، 1500...).
2. **قيم ناعمة**: الخلايا المتجاورة تتغير قليلًا، لأن المحرك فيزياء لا قفزات.
3. أحيانًا **رأس** قبله فيه الأبعاد نفسها.

هذا باحث مصغّر: يقرأ الملف كلمات 16 بت، ويجد كل تسلسل متزايد طوله 8 أو أكثر:

```python run
import random
import struct

rnd = random.Random(7)
image = bytearray(rnd.randrange(256) for _ in range(2048))      # «كود» عشوائي
axis = [600 + 400 * i for i in range(12)]
image[0x300:0x300 + 24] = struct.pack(">12H", *axis)            # محور مخفي عند 0x300
image[0x500:0x500 + 16] = struct.pack(">8H", *[10, 20, 30, 45, 60, 80, 100, 120])

words = struct.unpack(f">{len(image) // 2}H", image)
i = 0
while i < len(words):
    j = i
    while j + 1 < len(words) and words[j + 1] > words[j]:
        j += 1
    if j - i + 1 >= 8:
        print(f"axis candidate at 0x{2 * i:04X}: {j - i + 1} points, {words[i]} .. {words[j]}")
    i = j + 1
```

```text output
axis candidate at 0x0300: 14 points, 600 .. 62052
axis candidate at 0x0500: 9 points, 10 .. 45819
```

لاحظ أن المحورين **امتدا** بكلمات عشوائية بعدهما صادف أنها أكبر (12 نقطة صارت 14، و 8 صارت 9). لهذا لا يكفي «متزايد»؛ الباحث الحقيقي يفحص أيضًا انتظام الخطوات ونعومة القيم بعد المحور.

باحث RAD IDE أذكى بكثير: يجرب 8 و 16 بت (الترتيبين، بإشارة وبلا إشارة، بكل محاذاة) و float32، وأربعة أشكال (رأس Bosch للخريطة والمنحنى، وبلا رأس)، والقيم صفًا بصف أو عمودًا بعمود. ثم يعطي كل مرشح **درجة** من نعومة القيم وجودة المحور وحجم الجدول ودليل الرأس، ويحذف المتداخل.

```fwpy run
from radide.firmware.maps.finder import find_maps
from radide.firmware.maps.synth import build_image

data, truth = build_image(seed=1, size=0x10000)      # 64 KB اصطناعي فيه 7 جداول معروفة
cands = find_maps(data, max_results=20)
true_addrs = {m.address for m in truth}
top = cands[:len(truth)]
for c in top[:4]:
    print(c.label(), "<- real" if c.address in true_addrs else "")
print(f"{sum(c.address in true_addrs for c in top)} of the top {len(top)} are real maps")
```

```text output
0xAE7C  20x16  u16  97 <- real
0x8018  12x10  u8  96 <- real
0x87D4  16x12  s16  96 <- real
0x9EC1  16  u8  88 <- real
7 of the top 7 are real maps
```

## في RAD IDE

- منضدة العمل: **Find Maps** (`Ctrl+M`) تملأ لوحة **Potential Maps**. انقر مرتين لمعاينة مرشح، ثم **Add to Map Pack** لإضافته إلى مشروعك.
- محرر الخرائط الكامل (**Tools > Firmware & ECU > Calibration Maps > Find Maps in a Binary...**): البحث يعمل في الخلفية، وتبقى الواجهة حرة.
- إن رأيت الجدول بنفسك في محرر السادس عشر: حدده واضغط **K** (Map from Selection) أو اختر **Open in Map Editor** من القائمة اليمنى لمحرر السادس عشر.
- تبويب **2D View**: الملف كله منحنى واحد (8 أو 16 بت). الخرائط تظهر **أسنانًا منتظمة** متكررة، والكود ضجيجًا. انقر على السن لتذهب إليه.

> الباحث يقترح ولا يجزم: خريطة مربعة لا يُعرف إن كانت صفًا بصف أو عمودًا بعمود، والجدول بلا محور يحصل على درجة أقل. أكّد دائمًا بالمراجع من الكود (الدرس 4) أو بملف A2L (الدرس 6).
