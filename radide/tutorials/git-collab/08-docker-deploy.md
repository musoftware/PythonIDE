# الدرس 8: Docker والنشر إلى السحابة

**في هذا الدرس ستتعلم:**

- ما هي **الحاوية** (Container) و**الصورة** (Image) و `Dockerfile`.
- إنشاء `Dockerfile` و `compose.yaml` تلقائيًا من **Tools > Docker > Generate Dockerfile / Compose / Dev Container...**.
- فحص `Dockerfile` بـ **Lint Dockerfile** وفهم تحذيراته.
- **لوحة Docker**: الحاويات والصور و Compose والسجلات.
- **النشر** إلى Vercel و Netlify و GitHub Pages و Azure و AWS و Render و Railway وخادم SSH.

## حاوية الشحن

قبل اختراع **حاوية الشحن** كانت كل بضاعة تُحمَّل بطريقتها: صناديق وأكياس وبراميل، وكل ميناء يتعامل معها بشكل مختلف. ثم جاءت الحاوية الحديدية الموحدة: أي بضاعة داخلها، وأي سفينة أو قطار أو شاحنة تنقلها بالطريقة نفسها.
**Docker** يفعل هذا للبرامج: تضع برنامجك **مع كل ما يحتاجه** (النظام، Python بإصدار محدد، المكتبات) في حاوية، فيعمل بالطريقة نفسها على جهازك وجهاز زميلك والخادم السحابي.

| المصطلح | المعنى | التشبيه |
|---|---|---|
| `Dockerfile` | وصفة بناء الصورة: خطوات مكتوبة | قائمة ما يوضع في الحاوية |
| الصورة (Image) | النتيجة الجاهزة بعد تنفيذ الوصفة | حاوية مغلقة جاهزة للشحن |
| الحاوية (Container) | صورة **تعمل** الآن | حاوية تُفرَّغ وتُستخدم |
| `compose.yaml` | تشغيل عدة حاويات معًا (الموقع + قاعدة البيانات) | قطار من عدة حاويات |

> 💡 تحتاج إلى **Docker Desktop** (أو Podman Desktop) مثبتًا لبناء الصور وتشغيلها. أما **إنشاء الملفات وفحصها** فيعمل بدونه. البيئة لا تثبّت Docker بنفسها لأنه يحتاج صلاحيات المسؤول.

## إنشاء ملفات Docker تلقائيًا

**Tools > Docker > Generate Dockerfile / Compose / Dev Container...** (أو **Site > Docker** لمشروعات المواقع). نافذة **Generate Docker Files** (إنشاء ملفات Docker):

| الخانة | الاسم العربي | المعنى |
|---|---|---|
| **Project folder:** | مجلد المشروع | |
| **Project type:** | نوع المشروع | تكتشفه البيئة: Django و Flask و FastAPI و Node و Next.js و PHP و Laravel و ASP.NET و Spring و Rails و Go ... |
| **Port:** | المنفذ | المنفذ الذي يستمع عليه موقعك |
| **Database service:** | خدمة قاعدة البيانات | إضافة PostgreSQL أو MySQL أو Redis إلى `compose.yaml` |
| **Versions:** | الإصدارات | إصدار Python أو Node أو PHP |
| **Also generate:** | إنشاء أيضًا | **compose.yaml** و **.devcontainer/devcontainer.json** |
| **Live sync (docker compose watch)** | | تحديث الحاوية تلقائيًا عند الحفظ |
| **Overwrite existing files (a .bak copy is kept)** | | استبدال الملفات الموجودة مع نسخة احتياطية |

ثم **Preview** (معاينة) لترى الملفات، أو **Write Files** (كتابة الملفات)، أو **Write and Build Image** (كتابة الملفات وبناء الصورة).

### مثال: موقع Flask صغير

هذا مشروع Flask من ملفين:

<!-- test: {"dockergen": true} -->
```python
# #file: app.py
from flask import Flask

app = Flask(__name__)


@app.get("/")
def home():
    return "Hello from the container"
# #file: requirements.txt
flask
```

نوع المشروع المكتشف: **flask** على المنفذ **8000**. و `Dockerfile` الذي تنشئه البيئة:

```dockerfile
# syntax=docker/dockerfile:1
# Python - Flask - generated by RAD IDE (Docker > Generate Dockerfile). Edit freely.
FROM python:3.12-slim

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PIP_DISABLE_PIP_VERSION_CHECK=1
WORKDIR /app

COPY requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt \
    && pip install --no-cache-dir gunicorn==23.0.0

COPY . .

RUN useradd --create-home --uid 10001 app && chown -R app /app
USER app

EXPOSE 8000
CMD ["gunicorn", "--bind", "0.0.0.0:8000", "--workers", "3", "app:app"]
```

اقرأ الوصفة سطرًا سطرًا:

| التعليمة | المعنى |
|---|---|
| `FROM python:3.12-slim` | ابدأ من صورة جاهزة فيها Python 3.12 (نسخة خفيفة) |
| `WORKDIR /app` | المجلد الذي نعمل فيه داخل الحاوية |
| `COPY requirements.txt ./` ثم `RUN pip install ...` | انسخ قائمة المكتبات وثبّتها (قبل نسخ الكود، حتى لا يُعاد التثبيت مع كل تعديل) |
| `COPY . .` | انسخ كود المشروع |
| `USER app` | شغّل البرنامج بمستخدم عادي لا بصلاحيات المدير (أكثر أمانًا) |
| `EXPOSE 8000` | الموقع يستمع على المنفذ 8000 |
| `CMD [...]` | الأمر الذي يعمل عند تشغيل الحاوية (خادم gunicorn للإنتاج) |

وتنشئ أيضًا `.dockerignore`: قائمة ما **لا** يُرسل إلى البناء (`.git` و `.venv` و `__pycache__` و `.env` ...).

## فحص Dockerfile

**Tools > Docker > Lint Dockerfile** (فحص Dockerfile) يفحص الملف بثلاث طبقات: فاحص البيئة المدمج، و **hadolint** (زر **Get hadolint** ينزّله)، و `docker build --check` إن كان Docker يعمل. النتائج في قائمة الأخطاء بأرقام أسطرها.

هذا `Dockerfile` مكتوب على عجل، وفيه مشكلات كثيرة:

<!-- test: {"dockerlint": ["1 info RD003", "1 warning RD006", "2 info RD015", "3 error RD012", "4 error RD010", "6 warning RD008"]} -->
```dockerfile
from python
RUN cd /app && pip install flask
COPY app.py
EXPOSE web
CMD python app.py
CMD ["python", "app.py"]
```

ونتيجة الفحص:

| السطر | المستوى | الرمز | الرسالة | المعنى |
|---|---|---|---|---|
| 1 | info | RD003 | Instructions are usually upper case (FROM). | اكتب التعليمات بحروف كبيرة |
| 1 | warning | RD006 | Pin a version: 'python' means 'python:latest'. | حدّد الإصدار؛ `latest` يتغير مع الزمن فيكسر البناء فجأة |
| 2 | info | RD015 | Prefer WORKDIR over 'cd' in RUN. | استخدم `WORKDIR` بدل `cd` |
| 3 | error | RD012 | COPY needs a source and a destination. | `COPY` يحتاج مصدرًا ووجهة |
| 4 | error | RD010 | EXPOSE: 'web' is not a port number. | المنفذ رقم |
| 6 | warning | RD008 | Several CMD in one stage: only the last one counts. | `CMD` واحد فقط يعمل: الأخير |

وبعد الإصلاح لا تبقى أي ملاحظة:

<!-- test: {"dockerlint": []} -->
```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8000
CMD ["python", "app.py"]
```

## لوحة Docker

**Tools > Docker > Docker Panel** (لوحة Docker). تبويبات:

- **Containers** (الحاويات): الحاويات العاملة والمتوقفة؛ تشغيل وإيقاف وإعادة تشغيل وحذف وعرض السجلات.
- **Images** (الصور): الصور على جهازك؛ بناء وتشغيل وحذف.
- **Compose**: خدمات `compose.yaml`؛ و **Tools > Docker > Compose Up** يشغّلها كلها و **Compose Down** يوقفها.
- **Output / Logs**: مخرجات الأوامر وسجلات الحاويات.

و **Tools > Docker > Build Image** يبني صورة المشروع مباشرة. بعد **Compose Up** افتح المتصفح على `http://localhost:8000`.

## النشر إلى السحابة

**Tools > Deploy to Cloud / Git / SSH...** (أو **Site > Deploy to Cloud / Git / SSH...**) يفتح نافذة **Deploy - اسم المشروع**:

- يسارًا **Deploy profiles** (ملفات النشر): **New** و **Duplicate** و **Delete**. لكل ملف هدف وإعدادات.
- الأهداف المتاحة:

| الهدف | مناسب لـ | تسجيل الدخول |
|---|---|---|
| **Vercel** | مواقع الواجهات و Next.js | `npx vercel login` |
| **Netlify** | المواقع الثابتة | `npx netlify-cli login` |
| **GitHub Pages** | موقع ثابت من مستودع GitHub | `gh auth login` |
| **Azure App Service** | مواقع وخدمات .NET و Python و Node | `az login` |
| **AWS (Elastic Beanstalk / S3)** | تطبيقات وخدمات، أو موقع ثابت على S3 | `aws configure sso` |
| **Render (git push)** و **Railway** | تطبيقات بقواعد بيانات بسهولة | حسب الخدمة |
| **SSH server (rsync / SFTP + restart)** | خادمك الخاص | مفتاح SSH |

- الأزرار: **Check Sign-in** (التحقق من تسجيل الدخول)، و **Sign in (Terminal)...** (تسجيل الدخول (الطرفية)...)، و **Install CLI** لأداة الخدمة، و **Preview** (معاينة الأوامر)، و **Dry Run** (تشغيل تجريبي)، و **Deploy** (النشر)، و **Open Site** لفتح الموقع بعد النشر، وخانة **Production deploy** (نشر الإنتاج) بدل نسخة المعاينة.

> 🔒 البيئة **لا تسجّل الدخول نيابةً عنك أبدًا**. قبل النشر تتحقق بأمر قراءة فقط (مثل `vercel whoami`)، وإن لم تكن مسجّلًا تقول لك: "Sign in first" مع الأمر الذي تكتبه في الطرفية. وكلمات المرور والرموز السرية لا تُكتب في ملف المشروع.

**القاعدة الذهبية:** **Dry Run** أولًا: ترى الأوامر التي ستُنفَّذ والملفات التي ستُرفع **دون أن يتغير شيء**، ثم **Deploy**.

## أخطاء شائعة

- **"No Docker CLI found":** ثبّت Docker Desktop وأعد تشغيل البيئة. إنشاء الملفات يعمل بدونه.
- **`FROM python` بلا إصدار:** اليوم 3.12 وغدًا إصدار آخر يكسر البناء. حدّد الإصدار دائمًا.
- **نسخ `.env` وكلمات المرور داخل الصورة:** تأكد أنها في `.dockerignore`.
- **النشر مباشرة دون Dry Run:** قد ترفع المجلد الخطأ. عاين أولًا.
- **"Sign in first":** نفّذ أمر الدخول الظاهر في **View > Terminal** ثم **Check Sign-in**.

## تمرين

### مهمة عملية

1. أنشئ مجلدًا فيه `app.py` و `requirements.txt` من مثال Flask، وافتحه بـ **File > Open Folder...**.
2. **Tools > Docker > Generate Dockerfile / Compose / Dev Container...**: تأكد أن **Project type** هو Flask، وعلّم **compose.yaml**، ثم **Preview** و **Write Files**.
3. **Tools > Docker > Lint Dockerfile**. ثم اكتب `from python` في السطر الأول واحفظ وأعد الفحص؛ اقرأ التحذيرات وأعد السطر.
4. إن كان Docker Desktop مثبتًا: **Compose Up** وافتح `http://localhost:8000`، ثم **Compose Down**.
5. افتح **Tools > Deploy to Cloud / Git / SSH...**، وأنشئ ملف نشر **GitHub Pages** أو **Netlify**، واضغط **Dry Run** فقط.

## الخلاصة

- Docker حاوية شحن للبرامج: `Dockerfile` وصفة، والصورة نتيجتها، والحاوية صورة تعمل، و `compose.yaml` لعدة حاويات.
- **Tools > Docker**: **Generate Dockerfile / Compose / Dev Container...** و **Lint Dockerfile** و **Docker Panel** و **Build Image** و **Compose Up / Down**.
- **Tools > Deploy to Cloud / Git / SSH...**: ملفات نشر لكل هدف، و **Check Sign-in** ثم **Dry Run** ثم **Deploy**. البيئة لا تسجّل الدخول نيابةً عنك.
